# LOTTO LAB 5.2 번호 연쇄 연구실

기존 추천·실전 예측·구매 장부와 분리된 읽기 전용 연구 기능이다. 아래 결과는 역사적 자료를 분리한 평가이며 실제 추첨 전에 확정한 실전 예측이 아니다. 과거 결과를 본 사람이 설정을 반복해서 고르면 구간 분리만으로 사후 선택을 제거할 수 없다. 이 연구실의 결과는 기존 9개 추천 전략에 전달하지 않는다.

## 분석 정의와 데이터

- 입력은 `data/draws.json`의 본번호 6개다. 보너스·당첨금은 분석에 사용하지 않는다. 중복 회차·잘못된 본번호는 오류로 중단한다. 없는 회차를 다음 배열 원소로 대신하지 않는다.
- 기본 발견 구간은 1~1000회, 평가 목표 회차는 1001~1250회다. 평가 시작 경계의 과거 회차는 이미 알려진 조건으로 사용할 수 있다. 전이행렬도 이 규칙을 따른다.
- 기본 자동 탐색은 길이 2~10, 같은 간격 1~10회, 최소 발생 8회, 상위 12개 후보다. 번호별 관측 위치에서 실제 다음 회차의 6개 번호로만 확장하며, 빈발 접두사 가지치기와 150,000개 노드 예산을 적용한다. 높은 조건부 출현 편차 순으로 발견 구간에서만 후보를 고정한다.
- 11단계 이상도 입력할 수 있다. 발견 기간의 시간 범위, 최소 발생 수, 연산 예산 때문에 탐색이 끝나면 이유를 표시한다. 예산 종료 시 후보가 전부 탐색되지 않았음을 알린다.
- 사용자 지정 연쇄는 `5 / 12 / 7 / 9`, 집합 조건은 `5,12 / 7 / 9` 형식이다. 과거 2~5개 번호 집합을 각각의 단계에 넣을 수 있다. 각 단계에 최대 6개 본번호, 각 간격에 1~10회를 지정한다. 자동 집합 조합 탐색은 지원하지 않는다. 평가 결과를 보고 선택할 수 있는 사용자 지정 관계는 탐색용으로만 표시한다.
- 전체 연쇄 기대 횟수는 유효한 창 수 × 단계별 `C(6,k)/C(45,k)`의 곱이다. 마지막 단계의 조건부 기준 확률은 같은 포함 확률이며, 단일 번호이면 6/45다. 전체 연쇄 이후 다음 번호 분포는 연쇄의 마지막 단계 조건부 성적과 별도로 표시한다.
- 화면의 SHA-256은 입력 회차의 정규화된 자료 식별자다. UI 입력은 본번호/회차만 정규화하여 사용한다. 아래 명령의 재현 보고서는 원본 공개 자료의 날짜·보너스 등을 포함한 기존 `datasetStamp` 식별자를 사용한다. 기존 예측 기록의 해시와는 별개다.

## 검정과 선택 통제

단계 간 창이 겹치므로 조건 발생 횟수를 고정한 독립 이항 표본으로 취급하지 않는다. 목표 회차 이전에 알 수 있는 접두사로만 조건 발생 여부를 결정한다. 기준 조건부 확률을 `q`, 성공 수를 `S`, 조건 발생 수를 `N`이라 할 때, 고정된 12개 양·음 대안 `h`에 대해 `exp(h*S - N*log(1-q+q*exp(h)))`를 혼합한다. 공정한 추첨 아래 평균 1인 마팅게일이며, `min(1,1/E)`를 보수적인 p값으로 사용한다. 고정 후보 전체를 Holm 보정한다.

95% 구간은 같은 혼합 검정을 역산한 **후보별** 구간이다. 일정한 조건부 출현 확률을 가정한 보수적 구간이며 전체 후보의 동시 신뢰구간이 아니다. 경험적으로 시기마다 확률이 달라 보이는 경우 시간 구간별 표본과 함께 읽어야 한다.

몬테카를로는 발견 자료와 후보 선택을 고정하고 **평가 구간 전체**를 같은 회차 ID의 비복원 6/45로 다시 생성한다. 겹치는 접두사도 새 평가 이력에서 다시 검사한다. 발견 단계에서 선택한 과적합 후보가 독립 평가에서도 우연히 좋아지는지를 검정하므로 발견 과정을 같은 평가 자료에서 다시 최적화하지 않는다. 기존 공정 추첨 생성기(`fairNumberSource`, `fairDraw`)와 고정 시드를 재사용한다.

경험적 p값은 `(극단 반복 수+1)/(반복 수+1)`이며 개별 Holm 보정과 **고정 후보 전체의 최대 로그 E 분포**를 함께 제공한다. 기준 95% 시뮬레이션 구간도 제공한다. 조건부 비율의 기술적 구간은 조건이 1회 이상 발생한 반복에 한정하며, 검정 통계량에는 0회 발생 반복도 포함한다. 평가 조건 발생 20회 이상, 양의 효과, 해석적 Holm 및 MC Holm/최댓값 보정 모두 0.05 이하일 때만 재현 신호로 표시한다. 통과해도 미래 재검증을 요구한다.

설정·시드·기간을 반복해서 바꾸는 사용자 행동 전체에 대한 보정은 하지 않는다. 자동 발견 후보군만 확인적 평가 대상으로 삼고 임의 상세 조회/평가 히트맵은 탐색용이다. 가설 검정 통과와 추천 성과 개선은 별도로 표시한다.

방법 참고: [Ramdas et al., Game-theoretic statistics and safe anytime-valid inference](https://arxiv.org/abs/2210.01948). 이 자료는 원리를 설명하며, 구현은 겹치는 조건과 정확한 6/45 조합에 맞추어 별도 검증했다.

## 예측 평가 정책

- 발견 후보 접두사가 목표 회차 이전에 성립하면 마지막 번호에 발견 구간의 양의 출현 확률 차이만큼 가중치 `1+차이`를 더한다. 실제 평가 결과로 가중치를 조정하지 않는다.
- 이 실험 가중치로 첫 4게임을 비복원 추출한다. 기존 균등 무작위 전략과 같은 난수 흐름(`randomFor(round,10,seed)`)을 사용하고, 다섯 번째 공통 무작위 게임은 기존 전략의 실제 결과를 재사용한다. 활성 조건이 없으면 기존 무작위 5게임과 완전히 같다.
- 고정 모드는 1000회까지 고른 후보를 끝까지 유지한다. 워크포워드 모드는 50회마다 목표 회차 직전까지의 과거만 사용해 같은 탐색 규칙으로 갱신한다. 두 방식 중 좋은 것만 고르는 것을 고려해 성과 p값에 2배 보정을 적용한다.
- 비교는 동일 회차, 각 5게임이다. 과거 연속 50회가 없으면 양쪽 모두 제외하고 수를 표시한다. 한 회차의 게임들이 같은 결과를 공유하므로 게임을 독립 표본으로 계산하지 않는다.
- 각 번호의 두 전략 게임 포함 횟수 차이를 이용하고, 45개 중 6개를 고르는 정확한 조건부 MGF를 조합 DP로 구한다. 고정 양의 대안을 혼합해 회차 단위 검정한다. 대응 차이의 95% 순환 블록 부트스트랩(블록 10)은 **근사** 보조 지표이며 표본 20회 미만이면 계산하지 않는다.
- 순서대로 예측 → 해당 회차 채점 → 이력에 결과 추가 순서를 지킨다. `priorEnd`와 `fittedThrough`를 결과 JSON에 보관해 누수를 확인할 수 있다. 수익률/당첨금은 이번 연쇄 실험의 검증 지표에 포함하지 않는다.

## 실행 및 한계

기본 분석과 몬테카를로 모두 전용 Web Worker에서 실행한다. 진행률은 최대 약 180ms 간격으로 표시하고 취소하면 Worker를 종료한다. 취소한 계산은 결과로 저장하지 않는다. 내용 식별자·모든 설정·반복 수로 캐시하며 작업 종류별 최근 12개 결과까지만 메모리에 유지한다. 원본 자료가 바뀌면 표시 결과와 진행 작업을 무효화한다. 브라우저 구매 저장소와 기존 연구 아카이브에는 쓰지 않는다. 별도 JSON 내보내기로 전체 결과/설정을 보관할 수 있다.

몬테카를로 예상 연산량 `반복 수 × 평가 회차 수 × 후보 단계 수 합`이 300,000,000을 넘으면 실행 전에 이유를 표시한다. 기본 12개 3단계 후보의 100,000회 정밀 검정은 한도를 넘는다. 후보 수를 4개 이하로 **발견 단계에서 미리** 줄이면 250회 평가의 100,000회 검정이 가능하다. 평가 성적을 보고 후보를 줄인 결과를 원래 후보군 검정으로 취급하면 안 된다. 정밀 검정도 중간 진행률/취소를 제공한다.

기본 자동 탐색은 단일 번호 단계·같은 간격이다. 서로 다른 간격/번호 집합은 지정 조회로 지원한다. 자동 탐색의 모든 간격을 한 번에 최적화하지 않는다. 제한 없는 집합/간격 조합 탐색은 계산량과 다중 선택 문제 때문에 이번 범위에 포함하지 않는다.

### 실제 분석 결과 (2026-11-21 개발 검증)

93,141개 관측 노드를 검사하고 90,805개를 최소 표본 기준으로 가지치기했다. 4단계에서 8회 발생 조건을 만족하는 연쇄가 없어 그 이후를 중단했다. 10단계/11단계를 구현상 금지한 결과가 아니다. 자동 검출 12개 후보는 모두 3단계이며 평가 조건 발생은 후보별 1~6회뿐이다. 전부 **표본 부족**, 재현 검증 통과는 0개다.

**무작위 기준 대비 실제 예측력 개선을 확인하지 못했다.** 고정 정책은 3개 적중 25게임·4개 적중 1게임, 무작위는 26게임·1게임이었다. 양쪽 5·6개 적중은 0이다. 작은 평균 차이를 이득이나 당첨 확률 개선으로 표현하지 않는다.

간격 2·5·10의 추가 탐색도 각 10,000회 MC를 실행했다. 예측 평균 차이는 각각 -0.0032, +0.0064, -0.0024이며 두 방식 보정 p는 모두 1, MC 재현 통과 0개였다. 이 추가 설정은 탐색적 확인이며 좋은 간격을 선택한 확인적 성적으로 보고하지 않는다.

### 성능과 회귀 검증

- Node 기준: 기본 분석 약 52ms, 워크포워드 약 159ms, 기본 12개 후보 10,000회 MC 약 1.28초. 3개 후보 100,000회 MC 약 7.67초(동시 브라우저 검증 중 측정).
- Edge 158.0.4370.33 실제 Worker: 1365/390/360px에서 기본 분석 약 0.10~0.15초, 10,000회 약 1.85~1.88초, 동일 작업 캐시 약 22~27ms. 3개 후보 100,000회 약 7.5~7.9초. 기기/동시 부하에 따라 달라진다.
- 화면의 관계 선택/불규칙 간격 집합 조회, 잘못된 번호 오류, 11단계 입력, 진행률, 실행 중 취소, 연산 한도 거절, 캐시, JSON 결과 다운로드를 검증했다. 가로 문서 넘침·콘솔 오류·404가 없었고 연구 중 기존 브라우저 저장소 값이 그대로 유지됐다.
- 기존 9개 전략의 실제 1250회 사전 확정 번호/해시 재현, 구매 저장·수정·삭제/충돌 방지/백업 복원, 기존 몬테카를로·워크포워드·아카이브·해설 복사 및 수동 삭제 회귀를 검증했다. 신규 통계/누수/Worker 테스트를 포함해 Node 58개, Python 7개 통과. Pages 검토 산출물 빌드 및 모든 브라우저 모듈 문법 검사를 통과했다.
- 기존 전략 모듈, 구매 저장 코드, 공개 원본/예측/영수증/평가 데이터 및 운영 워크플로 파일은 수정하지 않았다. 기존 Worker 호출은 기본 경로를 그대로 쓰고, 작업 관리 함수에 새 Worker 경로 선택 인자만 추가했다.

화면 검증은 선택적 Playwright 실행이며 운영 의존성을 추가하지 않는다. 별도 개발 도구 위치를 지정할 수 있다. 먼저 위 Pages 빌드를 실행한 뒤 `LOTTO_PLAYWRIGHT_PATH`에 Playwright가 설치된 디렉터리를 지정하고 `node scripts/qa-chains.cjs`를 실행한다. Windows 기본은 Edge, 다른 환경은 Playwright Chromium이며 `LOTTO_BROWSER`로 실행 파일을 바꿀 수 있다. 격리된 브라우저와 로컬 HTTP 서버만 사용하며 원본 파일을 바꾸지 않고 1~1250회 응답을 테스트 고정 자료로 사용한다. 결과 화면은 `.test-tmp/chain-*.png`에 남긴다.
