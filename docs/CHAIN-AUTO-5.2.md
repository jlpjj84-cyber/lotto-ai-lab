# LOTTO LAB 5.2 자동 연쇄 분석과 10번째 실험 추천

이 문서는 v5.2.1 가중 무작위 방식의 보존 기록이다. 현재 v5.2.2는 [45개 점수·순위 기반 30개 선정](RANKED-SELECTION-5.2.2.md)으로 교체했고, 이 문서의 가중 무작위/다섯 번째 공통 게임 정책은 현재 점수 추천에 사용하지 않는다.

사용자 입력 없이 전체 확정 자료 → 조건 자동 발견 → 매회 워크포워드 평가 → 최신 자료로 다음 회차 5게임을 생성한다. 이전 5.2 수동 연구실과 9개 기존 전략은 유지한다. 이 문서는 방향 수정 이후 자동 기능을 설명하며, 초기 분리 연구실의 결과는 `CHAIN-LAB-5.2.md`에 보존한다.

## 작동 흐름

1. 기존 결과 갱신 워크플로가 공식 본번호를 반영한다. 같은 작업 안에서 `update-chain-auto.mjs`가 1회부터 최신 회차까지 읽는다. 별도 cron/외부 API 키/유료 AI를 추가하지 않는다.
2. 본번호·중복·공식 날짜·확정 시각을 검사한다. 1회부터의 연속 자료가 부족하면 부분 자료를 완전한 분석으로 취급하지 않고 균등 무작위로 대체한다. 잘못된/미확정 입력은 정상 분석으로 저장하지 않는다.
3. 자동 조건 탐색과 과거 매회 예측을 같은 상태 머신으로 재현한다. 현재 회차의 결과는 예측·채점을 끝낸 뒤 조건 집계에 추가한다. 마지막에는 최신 회차까지 모두 반영해 다음 회차용 후보를 고른다.
4. `data/chain-auto/latest.json`과 `snapshots/<최신회차>-<내용키>.json`을 저장한다. 스냅샷은 생성 전용이며 덮어쓰지 않는다. 내용키는 입력 SHA-256·전체 설정·알고리즘 버전으로 정한다. 임시 파일 완성 후 원자적으로 공개하며 중복 프로세스 잠금과 기존 Actions concurrency를 함께 사용한다.
5. 페이지는 서버 분석을 현재 자료의 해시/버전/설정과 대조한다. 일치하지 않으면 전용 Worker로 자동 재계산한다. 진행률을 표시하고 새 자료가 오면 오래된 계산을 취소한다. 같은 자료의 중복 알림은 다시 계산하지 않는다. 페이지가 보이는 동안 5분마다 기존 검증 데이터 갱신기를 조용히 호출하여 새 확정 결과를 확인한다.
6. 자동 결과는 별도 브라우저 키 `lotto_lab_v52_auto_chain`에 최대 3개까지 저장한다. 구매/기존 수동 기록은 변경하지 않는다. 저장 실패·손상은 이전 원본을 보존하고 표시한다. Worker 실패 시 평가 수치를 만들지 않고 균등 무작위 추천을 표시한다.

기존 일정인 토요일 18:00·21:00·22:20 KST 및 일요일 09:20 KST 작업을 재사용한다. 새 확정 결과가 없으면 같은 입력의 정상 저장본을 재사용한다. 자동 분석 실패는 `data/chain-auto/health.json`과 Actions 경고에 남긴다. 기존 원본 갱신·예측 검증은 독립적으로 진행하며 실패한 연구가 기존 정상 보고서를 덮어쓰지 않는다. Pages 빌드도 최신 자료와 맞는 분석만 포함하며 실패하면 새 배포 산출물 생성을 중단한다.

## 자동 탐색 대상과 계산 제한

- 단일 번호 A의 1~10회 후 번호 B 출현: 모든 본번호를 사용한다.
- 같은 과거 회차의 번호쌍 A&C → B: 회차 간격 1~10.
- 동일 간격 연쇄 A→B→C 및 마지막 간격 1인 혼합 간격 연쇄: 실제 관측 조건만 확장한다.
- 표본이 충분한 조건을 빔 확장하여 더 긴 시간 연쇄와 번호 집합+시간 조건을 발견한다. 기본 최대 길이 10이며 구조는 확장 가능하다. 제한 없는 모든 번호/간격 조합을 생성하지 않는다.
- 기본 최소 과거 조건 발생 8회, 대상 번호 성공 3회, 활성 후보 상위 24개, 빔 12, 추적 조건 50,000개, 대기 조건 60,000개, 회차별 긴 조건 교집합 질의 512개로 제한한다. 제한 발생은 화면/JSON에 기록한다. 이런 제한은 일부 후보를 누락할 수 있으며 전체 가능 연쇄의 완전 탐색을 의미하지 않는다.

과거 위치 목록의 교집합으로 긴 조건의 실제 과거 발생을 확인한다. 일단 등록한 긴 조건은 현재 탐색 빔 밖으로 나가더라도 이후 모든 발생을 계속 집계한다. 선택 근거는 번호의 전체 빈도 순위가 아니라 해당 시간/집합 조건 뒤의 출현 비율이다.

## 추천과 검증

조건별 긍정 편차 `(성공 수 − 조건 수×6/45)/(조건 수+20)`를 가중치에 더한다. 기본 가중치 1, 상한 2이며 이는 **추천 추출 가중치이고 실제 로또 당첨 확률이 아니다**. 상위 활성 후보만 사용해 첫 4게임을 비복원 추출하고, 다섯 번째 게임은 기존 균등 전략의 공통 무작위 게임을 그대로 재사용한다. 활성 조건이 없으면 기존 무작위 5게임과 완전히 같다.

각 추천 번호에는 실제 후보 수·가중치·영향을 준 조건 ID·조건 출현/성공 수·최근 성공 회차·검증 상태를 기록한다. 추가 패턴 가중치가 없는 번호와 공통 무작위 게임에 허위 선정 원인을 부여하지 않는다. 사용자 시드/게임 수/중복 제한 변경은 별도 설정이며 기본 평가의 직접 비교 대상으로 취급하지 않는다.

과거 평가는 기본 1001회부터 최신까지, **매 회차 직전 전체 이력**으로 후보/가중치를 다시 결정한다. 50회마다만 후보를 고정하는 평가가 아니다. 현재 추천과 같은 생성기·설정·난수 정책을 사용하며, 매 회차 양쪽 각 5게임을 비교한다. 겹치는 게임은 독립 표본으로 간주하지 않고 기존 정확한 6/45 회차 조건부 MGF 혼합 검정을 사용한다. 대응 차이 구간은 회차 블록 10의 근사 부트스트랩이다.

패턴별 발견에 사용한 과거 수치와 등록 이후 검증을 분리한다. 조건 등록 전의 과거 결과를 독립 검증에 재사용하지 않는다. 등록 순서 j에 `1/[j(j+1)]` 비중을 정하고 45개 결과에 나누어, 겹치는 조건의 혼합 검정 p에 `45×j×(j+1)`을 곱한 보수적 전역 보정을 한다. 등록 뒤 표본 20회 미만은 표본 부족이다. 방법 원리는 [순차 마팅게일 검정 자료](https://arxiv.org/abs/2210.01948)를 참고한다.

새 전략의 과거 성과는 역사적 워크포워드이며 실제 사전 확정 실전 성과가 아니다. 10개 항목의 사용자 추천 카탈로그를 따로 제공하고, 변경 불가인 기존 9개 사전 확정 전략 카탈로그와 해시 검증 경로를 그대로 둔다. 새 자동/수동 실험 번호는 기존 9개 실전 집계에 합산하지 않는다. 사전 공증을 포함한 10번째 실전 확정 파이프라인은 이번 범위에 포함하지 않는다.

## 실제 1~1251회 결과

알고리즘 v5.2.1, 시드 645. 49,656개 조건을 등록하고 현재 다음 회차 1252회에 성립하는 후보 24개를 사용했다. 최대 4단계 조건이 표본 기준을 충족했으며 계산 예산 제한은 발생하지 않았다. Node 24 기준 전체 계산 약 2.2~2.4초였다.

| 지표 | 연쇄 실험 | 기존 균등 무작위 |
|---|---:|---:|
| 평가 회차 | 251 (1001~1251) | 동일 |
| 평가 게임 | 1255 | 동일 |
| 평균 일치 | 0.794422 | 0.799203 |
| 3개 일치 게임 | 17 | 27 |
| 4개 일치 게임 | 2 | 1 |
| 5/6개 일치 게임 | 0/0 | 0/0 |

평균 차이 −0.004781개, 차이의 95% 근사 구간 −0.033466~0.022311, p=1이다. **무작위보다 높은 예측력을 확인하지 못했으며 관측 평균도 낮았다.** 그래도 사용자 선택에 따라 실험 추천은 사용할 수 있다.

현재 후보 예시는 `3회 전 2 & 1회 전 14 → 8`(과거 9/18), `8회 전 13+34 → 27`(10/22), `8회 전 34 & 4회 전 18 → 45`(11/26)이다. 모두 등록 후 검증 표본 부족이다. 현재 후보 중 등록 후 표본이 충분한 조건도 전역 보정 우위를 확인하지 못했다. 전체 후보/수치는 `chain-auto-1251-results.json`, 원본 분석과 추천 추적은 `data/chain-auto/latest.json`에 보관한다.

## 검증과 재현

```sh
node --test tests/*.cjs
python -m unittest discover -s tests -v
node scripts/update-chain-auto.mjs
python scripts/build_pages.py .test-tmp/auto-site
```

신규 테스트는 자동 10전략 카탈로그, 모든 본번호 읽기, 실제 조건 집계, 미래 결과 변조에 대한 이전 추천 불변성, 같은 과거 구간의 다음 추천/워크포워드 일치, 무작위 대체의 정확한 기존 번호 재현, 긴 조건의 모든 발생 집계, 해설/백업/중복 옵션, 자료 해시/저장 실패, 스냅샷 불변성·중복 잠금·실패 보존, 자동 서비스 취소/중복 알림을 포함한다. 기존 58개와 합계 Node 67개 및 Python 7개를 검증한다.

선택적 실제 브라우저 검증은 Playwright가 설치된 위치를 `LOTTO_PLAYWRIGHT_PATH`로 지정하고 `node scripts/qa-auto-chain.cjs`로 실행한다. 로컬 HTTP 및 격리 브라우저만 사용한다. 서버 저장본/브라우저 재계산/Worker 실패 시 대체, 자료 갱신, 10번째 수동 전략·복사·연구 백업·모바일·구매 보존을 확인한다. 운영 의존성을 추가하지 않는다.

실제 Edge에서 1365px 서버 저장본, 390px 브라우저 재계산, 360px Worker 실패 대체 경로를 통과했다. 별도 분석 입력 없이 5게임이 표시되고, 10개 전략 선택·번호별 근거·복사·아카이브·자료 변경 취소/캐시 복원·기존 수동 연구실을 확인했다. 문서 가로 넘침과 예상 밖 콘솔 오류/HTTP 실패가 없었으며 구매 저장값을 보존했다. 이번 로컬 환경의 페이지 진입부터 자동 결과 준비까지는 페이지 초기화를 포함해 약 21~23초였고, 연구 계산 자체는 약 2.2초였다. 전체 화면 초기화 시간은 계산 시간과 구분한다.
