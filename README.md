# LOTTO LAB 4.0 — GitHub 자동 갱신 웹 관제실

로또 6/45 **공개 추첨 결과**를 저장·분석하는 정적 웹사이트입니다. KStock과 별도 저장소로 운영합니다.

## 역대 패턴과 워크포워드 평가

- **역대 패턴**에서 회차별 특징과 해당하는 역대 회차를 열어볼 수 있습니다. 최근 20·50·100회 또는 전체에서 출현 횟수와 비율, 조합론 기대, 편차, 항목별 무작위 95% 기준을 비교합니다. 번호쌍과 3개 조합은 모든 조합을 집계하고 상위 12개를 표시합니다. 원하는 조합은 번호로 검색할 수 있습니다. 최근 출현 간격은 관측 가능한 연속 구간만 사용합니다.
- **특이성 검정**은 시드가 고정된 비복원 6/45 추첨으로 선택 구간 길이 전체를 1만 또는 10만 번 재현합니다. 95% 기준 구간은 반복 결과의 2.5·97.5 백분위입니다. 최다 번호쌍과 3개 조합은 각각 990개, 14,190개 후보 전체에서의 최대 횟수를 매번 비교합니다. 극값 이외의 지정 빈도는 이론 기대와의 절대 편차를 비교합니다. 관측과 같거나 더 극단적인 반복을 세어 `(건수 + 1) / (반복 + 1)`로 p값을 구합니다. 시드 645의 판정은 Holm 보정에 더해 4개 기간과 2개 반복 옵션을 보정합니다. 사용자 시드는 탐색용입니다.
- **전략 검증**은 회차당 5게임을 동일하게 비교합니다. 개발 구간은 1,000회까지, 평가 구간은 1,001회부터로 고정합니다. 직전 50회가 연속해서 있는 회차만 평가하고, 이전 데이터만 사용합니다. 가중 빈출·저빈출과 분산 조합은 조합 생성기와 동일한 수동 4게임 규칙을 쓰며 5번째는 공통 무작위 게임입니다. 전략과 파라미터를 바꾸면 기존 평가 결과는 탐색으로 해석해야 합니다.
- 전략 표의 95% 추정 구간은 회차 평균을 길이 10인 원형 블록으로 2,000번 재표집한 근사치입니다. 무작위 5게임 기준의 95% 범위는 같은 평가 회차·게임 수에 해당하는 일치 개수 분포를 1만 번 재현합니다. 각 전략의 단측 검정은 게임 사이 중복을 반영합니다. 해당 회차에 번호별 포함 횟수가 고정되면 45개 중 6개를 뽑는 조합론으로 지수 가중치의 기대값을 구할 수 있습니다. 관측 가중치를 그 기대값으로 나눈 값을 회차별로 곱하고, 사전에 정한 7개 가중 강도에 대해 평균한 뒤 역수(최대 1)를 p값으로 사용합니다. 8개 전략은 Holm 보정을 적용합니다. 미래 회차의 예측 우위는 별도로 검증해야 합니다.
- 모의 수익률에는 회차별 1게임 가격(87회까지 2,000원, 88회부터 1,000원)과 공시 세전 당첨금을 사용합니다. 5개 일치는 보너스로 등수를 나눕니다. 필요한 당첨금이 누락된 전략은 수익률을 비워둡니다. 드문 고액 당첨 한 건이 수익률을 크게 바꿀 수 있습니다.
- 통계 계산은 기본 화면에서 바로 표시되며, 몬테카를로와 전략 평가를 시작하면 Web Worker가 계산합니다. 결과는 브라우저 탭 메모리에만 캐시합니다. 구매 기록과 백업은 기존 저장 키와 형식을 그대로 사용합니다.

PR에서는 읽기 전용 CI가 단위 테스트와 Pages 산출물 생성을 실행합니다. 로컬 확인은 아래와 같이 산출물을 만든 다음 HTTP로 열 수 있습니다.

```sh
python -m unittest discover -s tests -v
node --test tests/test_dashboard.cjs tests/test_research.cjs
python scripts/build_pages.py _site
python -m http.server 8000 --directory _site
```

## 1회 설정 (GitHub 계정 주인)

1. GitHub에서 **New repository** → `lotto-ai-lab` → **Public** → Create repository. GitHub Pages 무료 배포를 위해 공개 저장소를 사용합니다. 개인 구매 기록이나 API 키를 저장소에 올리지 마세요.
2. 이 ZIP의 **폴더 내용**을 해당 저장소 `main` 브랜치에 업로드/커밋합니다. GitHub UI의 **Add file → Upload files** 화면에 압축 해제한 폴더 내용 전체를 드래그하거나, GitHub Desktop에서 커밋하세요. ZIP 파일 자체를 올리면 사이트로 배포되지 않습니다.
3. 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions** (별도 브랜치 배포 아님).
4. 배포 성공 후 주소: `https://<GitHub아이디>.github.io/lotto-ai-lab/` (계정명에 따라 바뀜). GitHub Actions의 `Publish latest dashboard + draw data` 작업이 웹 배포를 수행합니다.
5. **Actions → Lotto results — update verified draw data → Run workflow** 한 번 실행해 전체 과거 데이터 확보를 시도하세요. 이후 토요일 밤 22:20, 일요일 09:20 KST 예약 실행됩니다. 자동 커밋 후 같은 워크플로의 배포 작업이 최신 JSON을 웹에 게시합니다. GitHub 예약 작업은 지연·누락될 수 있으므로 일요일 결과를 확인해 주세요.

> GitHub에서 새 저장소를 만들고 이름을 알려주면, 연결된 GitHub 도구로 파일 업로드를 도와줄 수 있습니다. 현재 연동에서 새 저장소 생성 및 Pages 활성화 기능은 제공되지 않습니다.

## 보안·데이터 저장

- `data/draws.json`: **공개 당첨번호만** 저장. 1~1249회 이력을 확보했으며 이후 회차를 자동 갱신합니다. HTML에는 연결이 끊겼을 때 표시할 1150~1249회 자료가 내장되어 있습니다.
- 첫 Actions 실행은 외부의 MIT 공개 역사 데이터셋으로 이전 회차를 보충하고, 새 회차는 **동행복권 공개 조회 경로**에서 확인합니다. 수집이 실패하면 기존 데이터는 유지하며 로그에 오류가 기록됩니다. 과거 자료 출처: `JunKwon91/lotto-data` (MIT).
- 번호 생성/구매 기록은 사이트를 연 **해당 기기의 브라우저 localStorage**에 저장되고 GitHub에 전송되지 않습니다. 브라우저 데이터 삭제나 기기 변경 시 사라질 수 있으니 `데이터 관리 → JSON 백업`을 이용하세요.
- 기존 LOTTO LAB 2.0 구매 기록은 **2.0에서 전체 백업 JSON 다운로드 → 3.0에서 JSON 백업 불러오기**로 복원할 수 있습니다.
- 사이트는 실제 복권 구매를 하지 않습니다. 번호 자동 추천은 **예측력이 검증되지 않았으며**, 모든 조합의 1등 확률은 동일합니다.

## 수동 입력 및 장애 대응

공식 내부 조회 경로는 외부용 정식 API가 아니므로 차단 또는 변경될 수 있습니다. Actions가 실패하면 관리자만 `Run workflow` 입력란에 공식 발표 확인 결과를 입력하세요. 회차/날짜/6개 번호/보너스를 필수로 입력해야 합니다. 미래 회차, 충돌하는 회차, 불연속 회차는 거부됩니다.

데이터 동기화가 안 될 때에는 사이트에서 **데이터 관리 → CSV 파일 불러오기**를 사용할 수 있지만 이는 **해당 브라우저에서만** 적용됩니다. 공개 GitHub 데이터는 Actions 또는 커밋으로 갱신해야 합니다.
