# LOTTO LAB 5.2.2 — 로또 6/45 연구실

로또 6/45 **공개 추첨 결과**를 저장·분석하는 정적 웹사이트입니다. KStock과 별도 저장소로 운영합니다.

## 번호 연쇄 연구실 (5.2)

**전체 이력 분석 → 45개 전체 점수 → 순위 → 매 게임 6개 선정 → 선정 근거 기록**이 기본 동작입니다. **10번째 ‘연쇄 패턴 기반 실험 추천’**의 5게임/30개 위치 모두 점수와 명시적인 분산 감점으로 결정합니다. 가중 무작위 추출·무작위 채우기·다섯 번째 게임 무작위 고정은 점수 추천에 사용하지 않습니다. 무작위는 별도 대조군으로 선택합니다. 기존 수동 연구실은 선택 기능으로 유지합니다.

기존 결과 갱신 Actions 안에서 분석 JSON과 변경 불가 스냅샷을 저장하며 예약을 추가하지 않습니다. 서버 저장본이 현재 자료와 다르면 브라우저 Worker가 자동 재계산하고 별도 저장합니다. 조건 표본이 없으면 점수 0과 동점 규칙을 명시합니다. 분석 실패/자료 불완전 시 점수 추천을 중단하고 대조군을 별도로 제공합니다. 기존 9개 전략의 사전 확정 번호/해시 및 구매 데이터는 유지합니다.

현재 1~1251회 자료의 순차 평가(1001~1251회)에서 실험 평균 적중 0.812749개, 무작위 0.799203개, p=1로 **예측 우위를 확인하지 못했습니다**. [새 점수식·실제 5게임·30개 선정 과정](docs/RANKED-SELECTION-5.2.2.md), [독립 검증 원자료](docs/ranked-selection-1251-audit.json)를 확인하세요. 이전 [5.2.1 설계](docs/CHAIN-AUTO-5.2.md)와 [결과](docs/chain-auto-1251-results.json)는 보존 기록입니다.

선택적 기존 수동 연구실에서는 길이 2~10 및 그 이상의 관측 연쇄, 1~10회 간격의 45×45 전이행렬, 번호 집합 조건, 발생 회차와 이후 분포를 살펴볼 수 있습니다. 기본 1~1000회에서 후보를 고정하고 1001회 이후에 평가합니다. 고정 시드 비복원 6/45 몬테카를로, 후보 전체 보정, 회차 단위 예측 비교를 제공하며 고비용 계산은 전용 Worker에서 진행률·취소·캐시를 지원합니다.

수동 연구실의 결과는 기존 9개 추천과 구매 기록에 자동 반영하지 않습니다. 초기 1~1250회 분리 평가에서도 무작위 대비 예측력 개선을 확인하지 못했습니다. 초기 [분석 설계·제한·재현 방법](docs/CHAIN-LAB-5.2.md)과 [실제 수치](docs/chain-lab-1250-results.json)는 보존합니다.

## 사전 확정 예측과 실전 평가

| GitHub Actions UTC | 한국시간 | 처리 |
|---|---|---|
| `0 9 * * 6` | 토요일 18:00 | 대상 회차 조합 생성 및 GitHub 확인 |
| `0 12 * * 6` | 토요일 21:00 | 공식 결과 1차 갱신, 평가, Pages 반영 |
| `20 13 * * 6` | 토요일 22:20 | 결과 갱신 재시도, 평가, Pages 반영 |
| `20 0 * * 0` | 일요일 09:20 | 결과·당첨금 재확인 및 Pages 반영 |

동일 워크플로와 동시 실행 그룹을 사용합니다. 수동 실행은 `predict` 또는 `update-evaluate`를 선택합니다. 추첨 전 모드는 토요일 18:00~20:00 KST만 신규 기록을 생성하며, 공식 최신 결과와 저장된 직전 회차가 일치해야 합니다. 20:00 KST는 공식 추첨 예정 시각보다 앞선 프로젝트 확정 마감입니다. 예약은 지연될 수 있으므로 화면에 미확정과 미반영을 표시합니다.

- `data/predictions/<회차>.json`은 전략 버전, 시드, 데이터 기준 회차, KST·UTC 시각, 입력 SHA-256과 예측 SHA-256을 저장합니다. 회차당 각 전략 5게임을 별도 커밋으로 먼저 푸시합니다. 기존 파일은 변경하지 않습니다.
- 5.0 이후의 사전 확정 기록은 선택 과정, 참고 통계, 그때까지의 워크포워드 성과도 같은 SHA-256으로 검증합니다. 예전 기록에는 생성 당시의 설명이 없는 것으로 표시합니다.
- `data/prediction-receipts/<회차>.json`은 동일 커밋 SHA의 GitHub 상태 기록 ID와 GitHub 서버 `created_at`을 보관합니다. 평가 시 GitHub API에서 상태와 Actions 실행 출처를 다시 검증합니다. 같은 커밋의 `data/draws.json` 해시와 전체 추천번호를 재현하며, 예측 파일 변경 이력이 있거나 마감 전 서버 증빙이 없으면 실전 성과에서 제외합니다. 상태 확인이 마감 뒤에 기록된 예측도 제외합니다.
- `data/evaluations/<회차>.json`은 운영사의 공식 본번호·보너스를 공개 아카이브와 대조한 뒤 게임별 일치 수·등수·세전 금액을 저장합니다. 당첨금 자료가 뒤늦게 확보되면 이전 평가를 `data/evaluation-revisions/`에 보존하고 금액만 보완합니다.
- Pages는 `data/live/index.json`과 회차별 공개 상세를 만듭니다. 누적 성과는 전체 유효 평가를 사용하고 같은 회차의 무작위 5게임과 비교합니다. 20회 미만은 표본 부족으로 표시합니다. 과거 워크포워드 결과와 공개 사전 예측 결과는 화면에서 각각 확인할 수 있습니다.

GitHub 상태 기록은 저장소 권한의 보호를 받는 서버 증빙입니다. 저장소 관리자의 권한 변경이나 GitHub 자료 삭제까지 방지하는 외부 공증은 제공하지 않습니다. `GITHUB_TOKEN` 외의 별도 비밀키는 필요하지 않으며, 토큰은 워크플로에서 `contents: write`, `statuses: write`, `actions: read` 권한을 사용합니다. 실제 예약·공식 데이터 연동은 운영 브랜치 활성화 이후에 확인할 수 있습니다.

## 전략 선택형 수동 생성

조합 생성에서 9개 전략, 1~20게임, 동일 조합 제한, 게임 간 번호 중복 금지, 시드를 선택할 수 있습니다. 번호를 모두 분산하는 옵션은 7게임까지이며, 패턴 필터와 같은 조건을 동시에 만족하기 어려우면 실패 이유를 표시합니다. 기본 5게임·시드 645·추가 제약 없음은 4.0의 전략 평가와 같은 조합입니다. 사용자 시드 또는 게임 수·제약을 바꾸면 백테스트 수치는 전략 참고 성적으로만 표시합니다.

수동 생성 기록은 `lotto_lab_v41_generated_records`에 저장합니다. **추천 전략 및 공통 검증 요약**에서 적용 전략, 번호 생성 방식과 당시 연결된 검증 결과를 묶음마다 한 번 보여 줍니다. **개별 추천 해설**은 해당 게임의 실제 추출과 선정 후 확인한 조합 특징을 각각 설명합니다. 기본 공통 무작위 게임과 번호 분산 옵션을 적용한 무작위 게임은 각 후보 범위를 표시합니다. **자세한 선정 근거 보기**에서 번호별 가중치, 우선순위, 후보 수와 참고 통계를 확인할 수 있습니다.

**추천 보고서 복사** 및 **연구 아카이브**에도 같은 해설을 사용합니다. 화면을 표시하거나 보고서를 복사할 때 기존 근거에서 문장을 만들므로 해설은 저장 기록의 SHA-256 계산에 들어가지 않습니다. 선정 근거가 없는 과거 기록은 기존 안내 문구를 표시합니다.

연구 아카이브에서는 수동 추천과 실험을 각각 JSON으로 내보내고 복원합니다. 동일 ID의 다른 내용은 덮어쓸 수 없습니다. 새 기록은 SHA-256으로 내용 변경 여부를 검사합니다. 기기 시각과 브라우저 저장소에 의존하는 수동 기록은 별도 기기에서 시각을 증명하지 못하므로 GitHub 사전 확정 성과에 포함하지 않습니다. 기기를 바꾸거나 브라우저 저장소를 정리하기 전에는 연구 JSON을 내보내세요. 구매 기록과 구매 백업은 원래 키와 형식을 사용합니다.

## 역대 패턴과 워크포워드 평가

- **역대 패턴**에서 회차별 특징과 해당하는 역대 회차를 열어볼 수 있습니다. 최근 20·50·100회 또는 전체에서 출현 횟수와 비율, 조합론 기대, 편차, 항목별 무작위 95% 기준을 비교합니다. 번호쌍과 3개 조합은 모든 조합을 집계하고 상위 12개를 표시합니다. 원하는 조합은 번호로 검색할 수 있습니다. 최근 출현 간격은 관측 가능한 연속 구간만 사용합니다.
- **특이성 검정**은 시드가 고정된 비복원 6/45 추첨으로 선택 구간 길이 전체를 1만 또는 10만 번 재현합니다. 95% 기준 구간은 반복 결과의 2.5·97.5 백분위입니다. 최다 번호쌍과 3개 조합은 각각 990개, 14,190개 후보 전체에서의 최대 횟수를 매번 비교합니다. 극값 이외의 지정 빈도는 이론 기대와의 절대 편차를 비교합니다. 관측과 같거나 더 극단적인 반복을 세어 `(건수 + 1) / (반복 + 1)`로 p값을 구합니다. 시드 645의 판정은 Holm 보정에 더해 4개 기간과 2개 반복 옵션을 보정합니다. 사용자 시드는 탐색용입니다.
- **전략 검증**은 회차당 5게임을 동일하게 비교합니다. 기본값은 개발 1~1,000회, 평가 1,001회부터입니다. 학습 시작·평가 기간과 확장형/이동형 학습창을 바꿀 수 있습니다. 직전 50회가 연속해서 있는 회차만 평가하고, 제외 이유와 회차별 누적 흐름을 제공합니다. 가중 빈출·저빈출과 분산 조합은 조합 생성기와 동일한 수동 4게임 규칙을 쓰며 5번째는 공통 무작위 게임입니다. 조건을 바꿔 얻은 결과는 탐색용입니다.
- 전략 표의 95% 추정 구간은 회차 평균을 길이 10인 원형 블록으로 2,000번 재표집한 근사치입니다. 무작위 5게임 기준의 95% 범위는 같은 평가 회차·게임 수에 해당하는 일치 개수 분포를 1만 번 재현합니다. 각 전략의 단측 검정은 게임 사이 중복을 반영합니다. 해당 회차에 번호별 포함 횟수가 고정되면 45개 중 6개를 뽑는 조합론으로 지수 가중치의 기대값을 구할 수 있습니다. 관측 가중치를 그 기대값으로 나눈 값을 회차별로 곱하고, 사전에 정한 7개 가중 강도에 대해 평균한 뒤 역수(최대 1)를 p값으로 사용합니다. 8개 전략은 Holm 보정을 적용합니다. 미래 회차의 예측 우위는 별도로 검증해야 합니다.
- 모의 수익률에는 회차별 1게임 가격(87회까지 2,000원, 88회부터 1,000원)과 공시 세전 당첨금을 사용합니다. 5개 일치는 보너스로 등수를 나눕니다. 필요한 당첨금이 누락된 전략은 수익률을 비워둡니다. 드문 고액 당첨 한 건이 수익률을 크게 바꿀 수 있습니다.
- **몬테카를로 연구실**은 워크포워드와 같은 평가 회차로 1만 또는 10만 개의 독립 추첨 경로를 시뮬레이션합니다. 모든 전략은 같은 가상 당첨 결과를 함께 사용합니다. 과거 조합 고정 방식은 실제로 과거에 생성된 조합을 일정하게 둡니다. 순차 갱신 방식은 평가 시작 전 이력만 실제 자료로 쓰고, 각 실험에서 새로운 가상 이력으로 다음 추천을 갱신합니다. 두 방식의 합성 95% 범위는 관측 점수의 부트스트랩 구간과 별도입니다. 무작위 대비 단측 경험적 p값의 Holm 보정은 이번 실행에서 비교한 전략 수에 한정합니다. 설정을 반복 선택할 때 생기는 편향이나 미래 우위는 이 값으로 검증할 수 없습니다.
- **기준선 확인**. 추천 한 게임이 번호 6개면 기대 적중은 `6×6/45 = 0.8`개입니다. 1,001~1,250회는 결측 없이 250회입니다. 회차당 한 게임이면 기대 합계 200개, 이 프로젝트의 회차당 5게임이면 1,250게임에 기대 합계 1,000개입니다. 166.7개는 번호 5개짜리 한 세트를 250번 비교한 기대값에 해당하며, 기존 코드의 이 구간과 실제 평가 건수는 일치하지 않습니다.
- 시뮬레이션은 Web Worker에서 실행하며 진행률과 취소를 제공합니다. 특히 전체 전략의 순차 갱신은 평가 기간과 반복 수에 비례해 오래 걸립니다. 결과를 저장하면 데이터 SHA-256, 회차 범위, 평가 설정, 전략·모델 버전, 시드, 반복 수까지 함께 보존합니다.

PR에서는 읽기 전용 CI가 단위 테스트와 Pages 산출물 생성을 실행합니다. 로컬 확인은 아래와 같이 산출물을 만든 다음 HTTP로 열 수 있습니다.

```sh
python -m unittest discover -s tests -v
node --test tests/*.cjs
python scripts/build_pages.py _site
python -m http.server 8000 --directory _site
```

## 1회 설정 (GitHub 계정 주인)

1. GitHub에서 **New repository** → `lotto-ai-lab` → **Public** → Create repository. GitHub Pages 무료 배포를 위해 공개 저장소를 사용합니다. 개인 구매 기록이나 API 키를 저장소에 올리지 마세요.
2. 이 ZIP의 **폴더 내용**을 해당 저장소 `main` 브랜치에 업로드/커밋합니다. GitHub UI의 **Add file → Upload files** 화면에 압축 해제한 폴더 내용 전체를 드래그하거나, GitHub Desktop에서 커밋하세요. ZIP 파일 자체를 올리면 사이트로 배포되지 않습니다.
3. 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions** (별도 브랜치 배포 아님).
4. 배포 성공 후 주소: `https://<GitHub아이디>.github.io/lotto-ai-lab/` (계정명에 따라 바뀜). GitHub Actions의 `Publish latest dashboard + draw data` 작업이 웹 배포를 수행합니다.
5. **Actions → Lotto results — update verified draw data → Run workflow** 한 번 실행해 전체 과거 데이터 확보를 시도하세요. 이후 토요일 밤 21:00(1차), 밤 22:20(재시도), 일요일 오전 09:20 KST 예약 실행됩니다. 자동 커밋 후 같은 워크플로의 배포 작업이 최신 JSON을 웹에 게시합니다. GitHub 예약 작업은 지연·누락될 수 있으므로 일요일 결과를 확인해 주세요.

> GitHub에서 새 저장소를 만들고 이름을 알려주면, 연결된 GitHub 도구로 파일 업로드를 도와줄 수 있습니다. 현재 연동에서 새 저장소 생성 및 Pages 활성화 기능은 제공되지 않습니다.

## 보안·데이터 저장

- `data/draws.json`: **공개 당첨번호만** 저장. 1~1249회 이력을 확보했으며 이후 회차를 자동 갱신합니다. HTML에는 연결이 끊겼을 때 표시할 1150~1249회 자료가 내장되어 있습니다.
- 첫 Actions 실행은 외부의 MIT 공개 역사 데이터셋으로 이전 회차를 보충하고, 새 회차는 **동행복권 공개 조회 경로**에서 확인합니다. 수집이 실패하면 기존 데이터는 유지하며 로그에 오류가 기록됩니다. 과거 자료 출처: `JunKwon91/lotto-data` (MIT).
- 번호 생성/구매 기록은 사이트를 연 **해당 기기의 브라우저 localStorage**에 저장되고 GitHub에 전송되지 않습니다. 브라우저 데이터 삭제나 기기 변경 시 사라질 수 있으니 `데이터 관리 → JSON 백업`을 이용하세요.
- 기존 LOTTO LAB 2.0 구매 기록은 **2.0에서 전체 백업 JSON 다운로드 → 4.1에서 JSON 백업 불러오기**로 복원할 수 있습니다.
- 사이트는 실제 복권 구매를 하지 않습니다. 번호 자동 추천은 **예측력이 검증되지 않았으며**, 모든 조합의 1등 확률은 동일합니다.

## 수동 입력 및 장애 대응

공식 내부 조회 경로는 외부용 정식 API가 아니므로 차단 또는 변경될 수 있습니다. Actions가 실패하면 관리자만 `Run workflow` 입력란에 공식 발표 확인 결과를 입력하세요. 회차/날짜/6개 번호/보너스를 필수로 입력해야 합니다. 미래 회차, 충돌하는 회차, 불연속 회차는 거부됩니다.

데이터 동기화가 안 될 때에는 사이트에서 **데이터 관리 → CSV 파일 불러오기**를 사용할 수 있지만 이는 **해당 브라우저에서만** 적용됩니다. 공개 GitHub 데이터는 Actions 또는 커밋으로 갱신해야 합니다.
